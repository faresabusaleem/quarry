# Data: Brazilian E-Commerce Public Dataset by Olist

Generated by `make data` from the live DuckDB file. Do not edit by hand.

- **Source:** [Kaggle, olistbr/brazilian-ecommerce](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce), version 2.
- **Licence:** [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/). Real, anonymised commercial data released by Olist. Quarry uses it for a non-commercial portfolio demo with attribution.
- **Coverage:** about 99k orders placed between September 2016 and October 2018 (dense from January 2017 to August 2018).
- **Changes from the source:** typed columns, two typo fixes in column names (`product_name_lenght` and `product_description_lenght`), shorter geolocation column names, and six synthetic prompt-injection test rows in `order_reviews` (`review_id LIKE 'injtest-%'`). Nothing else is added or edited.

## Business glossary

These definitions are shared by the agent, the baseline and the ground-truth SQL.

- Currency: all money is in Brazilian reais (BRL, R$).
- Revenue / sales (default): SUM(order_items.price), excluding freight, over orders whose
  order_status is not 'canceled' or 'unavailable'.
- Number of orders: COUNT(DISTINCT order_id) with the same status filter, unless asked otherwise.
- That status filter applies to revenue and order counts only. Questions about payments,
  reviews, products, sellers or customers use all rows unless the user asks for a filter.
- Time: attribute orders to order_purchase_timestamp. Place a review in time by
  review_creation_date (when it was written), not by its order's purchase date.
- Reference date: the data ends in 2018. Treat "today" as 2018-09-01, so "last month" is
  August 2018, "last quarter" is 2018 Q2 (April-June) and "this year" is 2018 (Jan-Aug).
- Customer: a person is customers.customer_unique_id (customer_id changes per order).
- Category: use the English name, category_translation.product_category_name_english.
- Region: Brazilian states (customer_state / seller_state).

products.product_category_name *─1 category_translation.product_category_name

## `orders` (99,441 rows)

One row per order placed on the Olist marketplace (Brazil, Sep 2016 - Oct 2018). Use order_purchase_timestamp to place an order in time.

| Column | Type | Meaning |
|---|---|---|
| `order_id` | VARCHAR | Unique order identifier. |
| `customer_id` | VARCHAR | Key to customers.customer_id. Olist issues a new customer_id per order; use customers.customer_unique_id to identify a person across orders. |
| `order_status` | VARCHAR | delivered, shipped, canceled, unavailable, invoiced, processing, created, approved. |
| `order_purchase_timestamp` | TIMESTAMP | When the customer placed the order. |
| `order_approved_at` | TIMESTAMP | When the payment was approved. |
| `order_delivered_carrier_date` | TIMESTAMP | When the seller handed the order to the logistics partner. |
| `order_delivered_customer_date` | TIMESTAMP | Actual delivery date to the customer (NULL if not delivered). |
| `order_estimated_delivery_date` | TIMESTAMP | Delivery date promised to the customer at purchase time. |

## `order_items` (112,650 rows)

One row per item in an order. An order with three items has order_item_id 1, 2, 3. Item revenue is price; freight is charged separately in freight_value.

| Column | Type | Meaning |
|---|---|---|
| `order_id` | VARCHAR | Key to orders.order_id. |
| `order_item_id` | INTEGER | Sequence number of the item within the order. |
| `product_id` | VARCHAR | Key to products.product_id. |
| `seller_id` | VARCHAR | Key to sellers.seller_id. |
| `shipping_limit_date` | TIMESTAMP | Deadline for the seller to ship the item. |
| `price` | DECIMAL(10,2) | Item price in Brazilian reais (BRL), excluding freight. |
| `freight_value` | DECIMAL(10,2) | Freight charged for this item in BRL (order freight is split across items). |

## `order_payments` (103,886 rows)

One row per payment method used on an order. An order paid with a voucher and a card has two rows. Sum payment_value per order for the amount the customer paid (items plus freight).

| Column | Type | Meaning |
|---|---|---|
| `order_id` | VARCHAR | Key to orders.order_id. |
| `payment_sequential` | INTEGER | Sequence of the payment within the order. |
| `payment_type` | VARCHAR | credit_card, boleto (Brazilian bank slip), voucher, debit_card, not_defined. |
| `payment_installments` | INTEGER | Number of instalments chosen by the customer. |
| `payment_value` | DECIMAL(10,2) | Amount paid with this method, in BRL. |

## `order_reviews` (99,230 rows)

| Column | Type | Meaning |
